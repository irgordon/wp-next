# v0.0.6 — Import/Export Boundary Repairs

Recorded October 28, 2026. Closes the four findings from [v0.0.5](V0_0_5_REVIEW.md). Schema remains 8 and native format remains version 1.

## Corrections

1. **WXR inline attachments:** the parser retains attachment source URLs. Reference planning rewrites supplied image IDs/URLs and document links to mapped local assets before normal sanitization. It handles raw legacy HTML and HTML blocks inside nested columns; PNG and `.jpeg` inputs use the normal intake pipeline. Stale remote `srcset`/`sizes` attributes are removed. Missing attachments are reported, image elements are removed safely, link labels and ordinary UTF-8 text/captions survive. Remote fetching remains absent.
2. **Interrupted retry:** generated `_wpnext_import` provenance is included in the same canonical insert transaction as the Post, content and jobs. If later author/date bookkeeping or option checkpointing fails, retry locates the original Post by that identity, including a collision-suffixed Post. A per-run nonblocking file lock prevents concurrent application of the same archive/author mapping. Recovery does not add a revision or duplicate jobs. It preserves existing fallback dates and leaves later operator revisions intact.
3. **Social images:** supported `social_image_id` metadata is rewritten through the ready target-media map. An unmapped or non-image override is cleared with a result note, allowing the mapped featured-image fallback. Undeclared block media IDs cannot accidentally select an existing target ID. Source provenance/render bookkeeping is not trusted, copied or exported.
4. **Export bounds:** record counts are checked before export collection. The serialized manifest and deduplicated files are checked against importer limits for manifest bytes, ZIP entry count, largest entry and total uncompressed bytes. Exact 2,000-record output is accepted and can be parsed by the native importer; one excess record is refused before creating an archive. ZIP creation/add/close failures return an error and failed output is discarded.

## Structure And Compatibility

The new `portability-references.php` separates reference policy from DOM/database adapters. `wp_portability_remap_legacy()` reads as fragment → plan → missing references → rendered result. The new recovery and export modules isolate receipt queries, run-lock lifetime, source bookkeeping, bounds and ZIP writing. The procedural `wp_portability_run()` entry and normal mutation service remain in use; no executable source is imported.

`source_url` is an optional native version-1 field. Older exports remain readable, and content-addressed legacy image URLs can be reconstructed from their source home/hash. WXR run identity now includes both XML and supplied media ZIP bytes. Internal provenance is generated by the importer and omitted from exports.

Existing completed progress checkpoints remain compatible. The durable-receipt repair applies to items inserted by this version and later. Old uncheckpointed items without provenance and duplicates already created by earlier versions need operator review; this patch does not delete or rewrite that content automatically. The format's capacity remains bounded: use a normal site backup for data beyond those limits.

The scope is the four functional findings and the changed boundaries. It is not a full rewrite of the legacy WXR parser/preflight planner noted in v0.0.5. J1 production certification and the previously recorded intermittent issues remain separate.

## First Failures And Repairs

- PHPStan found an unnecessary nullsafe property access next to `??`; the redundant operator was removed. No type was widened and no analysis ignore was added.
- The first checkpoint regression exposed SQLite expression affinity: `json_extract()` produced an integer while PDO bound the comparison value as text. The repository query now explicitly casts that parameter to INTEGER. The actual interrupted-collision regression then passed.
- The new fixture module initially retained an extra blank line at EOF. It was normalized in its unpublished refactor commit before publication.
- Changed-line whitespace checks and the configured formatter pass. The original acceptance assertions remain intact; fixture setup was extracted rather than dynamically executed from another suite's source.
